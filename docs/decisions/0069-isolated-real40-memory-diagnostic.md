# ADR-0069: Isolated real40 memory diagnostic

Quality Campaign owns a nonqualifying installed diagnostic-run vertical slice.
It measures one frozen forty-question execution before the full 3x240 release
qualification. No diagnostic artifact admits serving or satisfies ADR-0066.

The owner declaration binds read-only PostgreSQL snapshot and transcript digests,
version, explicit human/automation roster, isolated diagnostic scope, source,
SDK, model and retrieval profile. It is not lifecycle provenance or reviewer
authority. A concrete PostgreSQL diagnostic adapter rechecks frozen source on
each rehydration. Its explicit diagnostic projection reuses deterministic block
planning and rehydration without manufacturing lifecycle v3.

The installed CLI indexes stable IDs through the official SDK only after retaining
an encrypted create-only plan. Questions start only after a complete applied
index receipt. An unknown index outcome stops; reconciliation uses the same IDs.
A frozen-plan adapter provides candidates without a duplicate historical store.

Production canonical chain constructor checks remain unchanged. A diagnostic
wrapper shares the private engine and accepts only concrete diagnostic adapters.
Original and repair calls each have durable create-only reservations before
provider bytes. Restart never blindly repeats an uncertain attempt.

The executor accepts only gold-free question packets. Forty remains the
denominator across answers, abstentions, failures, timeouts and unknowns.
Latency and bytes are measurements; valid citations are not factual accuracy.
Gold scoring is subsequent and factual accuracy remains unmeasured without
independent adjudication. Canonical transcripts and original recordings are
never mutation or cleanup targets.

Owned source paths are diagnostic-manifest.ts, diagnostic-frozen-store.ts,
diagnostic-custody.ts and diagnostic-run.ts under the existing classified
quality-campaign adapter; the PostgreSQL adapter remains in its existing closed
package boundary. No new package, table or dependency is introduced.

## Installed operation

Use the installed `discord-meeting-quality-campaign diagnostic-run` command with
absolute manifest and new public report paths. The manifest is the exact closed
`DiagnosticManifest` in `diagnostic-manifest.ts`; question entries contain only
locale, question ID, question text and a topology reference. Credentials remain
path-injected. Use a new isolated artifact root and a PostgreSQL read-only role.
The code additionally sets the session read-only. The declared Git revision is
reported as owner-declared/unverified; loaded runner and SDK bytes are hashed.

If indexing has an uncertain outcome, stop and explicitly invoke the same command
with `--reconcile-index` and the same manifest/artifact root but a fresh public
report path. The report is reserved create-only before effects; a failed or crashed
invocation can leave an empty placeholder, which must not be reused. It reuses the retained plan and
stable mutation/document IDs. It does not replay a question with an uncertain
original or repair call. Following questions remain failed in the denominator.

Only after complete execution, `discord-meeting-quality-campaign diagnostic-score`
accepts absolute manifest, execution report, separate retrieval gold and new score
report paths. Retrieval gold is an exact array of forty entries containing
`questionId`, `relevantTurnIds` and `expectedDisposition` (`answerable` or
`must_abstain`). The scorer authenticates the retained completion, plan and every
outcome before opening gold. Real plan turn-to-block mappings determine Recall@5,
Recall@10 and MRR@10. Factual accuracy remains unmeasured without adjudication.
These two diagnostic commands cannot produce a qualification admission receipt.
